### 1.2 【CONFIRMED】BALBCE−A0 不是"只隔离了类别均衡"

`blr.py:80-89`(A0)与 `blr.py:90-114`(其余 arm)的全部差异:

| 维度 | A0 | BALBCE |
|---|---|---|
| 类别比例 | 训练集真实先验 | 每步严格 50/50 |
| 采样 | 每 epoch 一次无放回置换 | 类内**有放回**独立抽样 |
| 每步样本数 | 64 | 1024 正 + 1024 负 = **2048** |
| 每 epoch 步数 | `ceil(n/64)` | `max(1, n//64)` |
| 每 epoch 样本呈现次数 | 恰好 n | ≈ 32n |
| 覆盖保证 | 每项恰好 1 次 | 无保证,可重复 |

所以 BALBCE−A0 = (类别均衡) + (每步 batch ×32) + (有放回重采样) + (可能少一步)。R8 自己的候选表里
就有 `C12 PAIRSAMP — pair count as effective sample size`(`IDEA_REPORT.md:3124`),即这个替代解释
项目内部已经命名过,但没有被隔离掉。

佐证:A0 的 seed 标准差在 4 个数据集上都最大(HateMM 0.0115 vs BALBCE 0.0055;MHC 0.0132 vs
0.0045),这正是小 batch 高梯度噪声的形态,不是类别比例造成的。

**受影响的还有 §11.4 建议 1**("Bank balanced sampling as the per-dataset default,
+0.0065 / +0.0163 / +0.0106")。这三个数是 BALBCE−A0 的 P1 值,是**整个配方**的效应,不是均衡的效应。
要单独归因给均衡,需要再加一个 arm:同样 2048/步、有放回、但按真实先验抽样。

### 1.3 【CONFIRMED】被 R8 解释掉的 ensemble 原始数字本身是 test 上取最大

`IDEA_REPORT.md:2136` 记录"+1.3 to +5.3 macro-F1 over the validation-best single encoder on all
four datasets"。其来源是 §8.7 的表(`IDEA_REPORT.md:2015-2021`),该表的"best ensemble comparator"
列是在 **5 个组合器(mean_logit / mean_prob / weighted / logistic / mlp)里按 test macro-F1 取最大**。

从 `idea-stage/r4_pilot1.json` 逐 seed 重算(3 seeds 平均):

| 数据集 | single(val 选的编码器) | **冻结组合器**(val 选,`frozen_comparator`) | Δ | test 上取最大 | Δ |
|---|---|---|---|---|---|
| HateMM | 0.8598 | mean_prob 0.8600 | **+0.0002** | mlp 0.8732 | +0.0134 |
| MHC-EN | 0.7358 | mean_prob 0.7702 | **+0.0344** | mean_logit 0.7776 | +0.0419 |
| MHC-ZH | 0.7655 | weighted 0.8009 | **+0.0353** | logistic 0.8183 | +0.0528 |
| ImpliHateVid | 0.9093 | mean_logit 0.9226 | **+0.0133** | logistic 0.9276 | +0.0183 |

**诚实的区间是 +0.02 到 +3.53 点,不是 +1.3 到 +5.3;HateMM 上是 +0.0002,即零。**

### 1.4 【CONFIRMED-minor】D1 的 ensemble 反驳换了估计量

`decomp.py:148`:`best = max(tags, key=lambda t: row["per_encoder_single"][t]["macro_f1"])` ——
用**同一份 OOF macro-F1** 既选 best 又当基线,是 oracle 选择。

但重算表明这不是驱动结论的因素:三个数据集上编码器差距很大(HateMM 0.8690 vs 0.8306 = 0.0384;
MHC 0.8217 vs 0.7536 = 0.0681;MHC_zh 0.8494 vs 0.7859 = 0.0635),选择身份稳定;唯一差距小的
ImpliHateVid(0.9121 vs 0.9106 = 0.0015)上 crossens 反而是**正的**(+0.0103)。所以 oracle 选择
偏差不足以翻转 3/4 的负号。

真正的问题是四条轴同时被换:

| 轴 | 原命题(§8.7/§8.10) | D1 |
|---|---|---|
| 组合器 | weighted / logistic / MLP(学习权重) | 等权平均 |
| 基线 | validation 选出的单编码器 | OOF-oracle-best 单编码器 |
| 评测集 | test(149–215 项) | train+val 5 折 CV |
| 读出 | val 选 epoch + val 选阈值 | 末 epoch @0.5 |

**Codex 的第 9 条主张"validation 选择不可能选错编码器,所以 encoder selection 解释不成立"——
这条被重算 REFUTED。** `r4_pilot1.json` 里每个 seed 的 `ref` 字段(即 val ROC 最优编码器)是:
HateMM `['QWEN','QWEN','QWEN']`、MHC `['QWEN','QWEN','QWEN']`、MHC_zh `['QWEN','LORA','QWEN']`、
ImpliHateVid `['CLIP','CLIP','CLIP']`。而 D1 的 CV 显示 LoRA 编码器在 HateMM/MHC/MHC_zh 上分别比
QWEN 高 0.0384 / 0.0681 / 0.0635 macro-F1。**val ROC 选择在 3/4 个数据集上确实选中了明显更弱的
编码器**,所以 R8 的 "encoder selection" 成分是真实的。

**结论**:D1 的"等权跨编码器平均输给最强单编码器"是正确的描述性事实(重算逐格核对:
−0.0068 / −0.0427 / −0.0190 / +0.0103,与 memo 一致);"ensemble line 主要是 encoder selection +
variance"这个**归因也有实证支持**(val 选错编码器);但 D1 **没有**直接反驳"学习型组合器相对 val
选出的编码器 +1.3~+5.3"这一条——真正削弱它的是 §1.3 的 test-取最大,而不是 D1。

### 1.5 【CONFIRMED-minor】RANDL arm 的 RNG 消耗

`blr.py:104`:`sel = torch.randperm(NPAIR, generator=g)`。`g` 与 `blr.py:92-93` 抽 `pi`/`ni` 用的是
**同一个** Generator。PAIRG / PAIRL 在这一步不消耗 `g`。因此 RANDL 从第 2 个 optimiser step 起,
配对序列与 PAIRL/PAIRG 完全不同。

后果:`PAIRL − RANDL`(冻结条件 4)不是共享 batch 的配对对比,是两条不同 Monte-Carlo 轨迹之差。
边际分布相同,所以**期望无偏,只是方差偏大**。KILL 判决不受影响(条件 1–3 已经先失败,且
PAIRL−RANDL 在 3/4 数据集上本来就是负的)。修法:给子集选择单独开一个 generator。

同时核实 **PAIRG−BALBCE 是干净的隔离**:两个 arm 每步都只调用两次 `torch.randint`,不消耗额外
随机数,同 seed 下索引序列逐步相同。§11.0 第一条依赖的正是这个对比,这部分**成立**。

### 1.6 【CONFIRMED-minor】三处措辞需要收窄

- §11.0 "averaging three seeds of the same encoder is positive in 4/4 on both macro-F1 and ROC" —
  只在 **FINAL 读出**下成立。TRAJ 读出的 `gain_seedens` 是 +0.0024 / **−0.0030** / **−0.0052** /
  +0.0021(`r8_decomp/results.json`)。§11.1 已限定"Final-epoch read-out",§11.0 的 bullet 没限定。
- §11.0 "adding the pairwise ranking loss ... every CI containing zero" — 指 macro-F1,4/4 正确
  (`[-.0023,+.0029]`、`[-.0026,+.0008]`、`[-.0017,+.0039]`、`[-.0004,+.0017]`)。但同句给出的 ROC
  值里 HateMM `[-.0015,-.0001]` 与 MHC `[+.0002,+.0028]` 的 CI **排零**,方向还相反。不影响结论
  (量级 ≤ 0.0014),但"排序项一无所获"更准确的说法是"macro-F1 上一无所获,ROC 上有 ±0.001 量级、
  方向不一致的可测效应"。
- `decomp3.py` 的 `tprior = np.quantile(pt, 1.0 - prior)` 用的是**评测折自身**的分数分布,是无标签

### 2.3 【CONFIRMED-minor】chance null 用错,0.5625 恰好等于多数类常数基线

32 行里 18 个金标 DISTANCED、14 个金标 ENDORSE。

- 恒答 DISTANCED = **18/32 = 0.5625**
- 恒答 ENDORSE = 14/32 = 0.4375
- Claude 三人多数票实测 = **0.5625**

`score_gate.py:95` 的 `binom_p(k, n, p=0.5)` 检验的是"是否优于公平硬币",报 p = 0.5966。
但真正该比的是多数类常数基线 0.5625,对它 Claude 的增益**恰好是 0**。
(Claude 并非恒答:call 分布是 DISTANCED 20 / ENDORSE 12。但信息增益为零。)

`CLAUDE_STANCE_GATE_RESULT.md` 里凡引用 "p vs chance 0.5 = 0.5966" 处应补一句
"对多数类常数基线(0.5625)增益为 0"。判决 FAIL 不变。

### 2.4 【无缺陷】0.563 判定线的取整

Claude 得 18/32 = 0.5625,写死的弱线是 `0.563`,所以 `0.5625 >= 0.563` 为假 → FAIL 而非 WEAK。
表面上是取整决定了判决,但:

1. 冻结文档 `CLAUDE_STANCE_GATE_FREEZE.md:118-119` 明写 "0.563 = qwen 最好的一轮,R2 二值化",
   而 qwen R2 在同样 32 行上的实测值(`score_c1.json` 的 `mask_binary_acc_S`)也是 **0.5625**;
   规则的语义是"不比 qwen 更好就 FAIL",**恰好打平属于"不更好"**,FAIL 是规则本意。
2. n=32 下相邻可取值是 18/32 = 0.5625 与 19/32 = 0.59375,**0.5625 与 0.563 之间没有可达值**,
   所以取整不改变任何可能结果的分类。

判决**正确,且不是碰巧正确**。建议在 RESULT 里把"低于 0.563"改写成"与 qwen R2 逐项打平(18/32 对
18/32),按冻结规则'不优于 qwen 即 FAIL'判 FAIL"。

### 2.5 【CONFIRMED-minor】contrast_stance 的 M2 是单边闸,对实际失败形态失效

`score_contrast.py:159-163`:`M2_pass = (CTRL_HATE 被判 OPPOSE 的比例 ≤ 0.15)`。
它设计来抓"恒答 OPPOSE"的退化预测器。

实测的 call 分布(`score_c1.json`,view A):S_FP {ENDORSE 19, OPPOSE 2}、S_FN {ENDORSE 14}、
CTRL_HATE {ENDORSE 18}、CTRL_NONHATE {ENDORSE 14, OPPOSE 4} —— **71 项里 65 项(91.5%)判 ENDORSE**,
即近乎恒答 ENDORSE。M2 得 0.0,**PASS**。

也就是说 M2 在实际发生的那个退化模式上完全失效。脚本算了 `ctrl_nonhate_said_ENDORSE`
(= 14/18 = 0.78,明显异常)但它**不进 VERDICT**(`score_contrast.py:163`)。

本轮判决 FAIL 不受影响(M1 = 0.469 先失败,而且恒答 ENDORSE 只能拿 14/32 = 0.4375,过不了 M1 = 0.70)。
但这是一个**结构性的闸门缺陷**:一个 M1 更高、同时 CTRL_NONHATE 塌陷的模型会拿到实质错误的 PASS。
后续任何复用这套闸门的实验,M2 必须双边化,并把 `ctrl_nonhate_said_ENDORSE ≤ 某界` 纳入 VERDICT。

### 6.6 【建议采纳】3-seed 结果的可报告规则

现行做法是看 "mean ≥ 界 且 3/3 seed 同号"。3/3 同号的符号检验双侧 p = 0.25,**永远达不到 0.05**,
所以这条规则本身不构成证据。改用:

> **一个冻结的 3-seed 配对 HateMM 对比,只有当它自身的双侧 95% 配对 t 区间排零时,才可以作为
> 方向性结论上报。** n=3、df=2 时这等价于 `|mean| > 2.484 · sd_Δ`。

配套三条:
1. MDE 必须逐对比算(3 seed 时 MDE₈₀ ≈ 2.97·σ_Δ),**不存在**一个通用的 0.0353。
2. 规划用的 σ_Δ 要来自同类对比的独立多 seed 先导,不能用本次观测到的 3-seed sd 反推功效。
3. "没有效应""近乎免费""内容不重要"这类陈述需要**预先声明等价界**并给等价区间,
   不能用"没有拒绝零"来代替。
