QTL：按需向 VLM 提问的仇恨片段定位

网络先给视频每一秒一个仇恨先验。然后在视频的二分时间树上挑片段问 VLM“这段有没有仇恨”，每个回答都通过树上的精确推断更新每一秒的仇恨概率。第 7 版做了两处改动：一是网络先验在测试视频上按权重 c 打折，c 只用 validation 视频的回答估计，不用标签；二是第一轮可以先问树上某一层的等长窗口，这一层的深度 d 在 validation 上选。

当前版本 = 第 7 版（用户 2026-11-14 指示采用）：第 6 版 + 位置先验权重 c + validation 选首层深度 d（experiments/20261110_prior_weight/README.md 第 8、10、12 节）。骨干结构、答案表、训练损失与第 6 版相同。共享代码在 src/qtl/。

1训练：一个训练视频怎么走

  • 负例视频：全部节点已知无仇恨，答案项是常数，只有 −log P(Y | x) 训练视频头 g。所以每秒势 s_t、节点势 φ_n 只由正例视频的多尺度答案训练。
  • 答案项除以答案数：长视频有上千个节点答案，除以答案数后每个视频权重相同。
  • 每个 epoch 结束后估一次 c第 7 版：用这个 epoch 的网络，在 validation 视频的缓存回答上估 c（不用标签，见第 3 节）；选 epoch 的 validation 指标在这个 c 下算。选中的 epoch 的 c 跟 checkpoint 一起存下，测试时用。
  • 搜索与选模型：每个 seed（234 / 2025 / 3407）20 个 Optuna trial，搜 lr、λ_cma、dropout、lr_answer；epoch 用 validation 固定问 8 次的 (AP+ROC)/2 选；训练结束后对每个报告预算在 validation 上选 d；trial 用 test 同一目标选（规则 7）。

2测试：一个测试视频怎么走

  • inside–outside：inside 自下而上算每个节点下面所有标注组合的总概率；outside 给出每秒、每节点的后验。代码里 outside 这一步用对 log Z 求导（autograd）实现，数值和 outside 传递相同（src/qtl/ctree.py 的 up、marginals）。
  • 报告用固定预算：主表是每个视频固定问 8 次（视频太短、可问节点不够时少于 8 次：平均 7.63 / 8.0 / 7.26 次）。按预算提前停的规则见第 5 节。

3第 7 版的两处改动

① 位置先验权重 c（不用标签估计）

网络的逐秒势 s_t 和节点势 φ_n 是在训练视频的回答上拟合出来的，到没见过的视频上预测得差很多，但树推断原来按满权重使用它们，回答和网络不一致时回答就被压下去。第 7 版在模型里给这两项乘一个标量 c，c 取使 validation 视频全部缓存回答的边际似然最大的值。视频头 g 不乘（它的权重无标签估不出来）。

P(G=1 | x) = sigmoid(g) 不变 P(y | G=1, x) ∝ exp(c · Σ_t s_t y_t) · chain(y) · Π_n exp(c · φ_n z_n) s_t、φ_n 乘 c c = argmax_c Σ_v log [ P(G=1|x_v) P(o_v | G=1, x_v; c) + P(G=0|x_v) P(o_v | G=0) ] v = validation 视频，o_v = 该视频全部节点的缓存回答；答案表、链固定；不用视频标签、不用逐秒标注 先在 13 个网格点上算似然，再从最好的点出发 L-BFGS（src/qtl/prior_weight.py，mode "loc"）
  • 估出来的 c 很小：60 个 trial 的中位数 HateMM .26、HCS .09、DeHate .18；test 选出的 trial 是 .11–.17、.02–.22、.06–.11。也就是网络的位置先验在没见过的视频上只该用约十分之一到四分之一。
  • 不需要额外的 VLM 调用：c 是部署模型的一个常数，用的是训练前已经抽好的 validation 回答。用户 2026-11-10 裁定：这样估计不属于规则 3 禁止的后处理校准。

② 首层深度 d（在 validation 上选）

提问策略是一族：先把树第 d 层的 2^d 个等长窗问完（按 EIG 排顺序），剩下的调用再在全部节点上按 EIG 贪心。d = 0 就是第 2–6 版的贪心树；预算正好 2^d 次时就是只问一层等长窗。训练结束后，对每个报告预算各自在 validation 上按 (AP+ROC)/2 选 d（0–3，预算更大时到 5）。视频太短、第 d 层不是每个窗都 ≥4 秒时，退到能全部问的最深一层（cpolicy.run_batch(first=)、search_first_level.py）。

4问题树：节点是什么

  • 每个节点有一个隐状态 z_n：区间里至少有一秒仇恨就是 1。视频标签就是根节点的 z。
  • 骨干在每一层都给先验：根用 g，内部节点用 φ_n（视频头的注意力池化在每个节点内部再做一次），叶子（单秒）用 s_t。第 7 版里 φ_n、s_t 乘 c。
  • 图中编号是 d = 0（贪心）的一种顺序。d = 2 时前 4 问是第三行的 4 个 8 秒窗；d = 3 时前 8 问是第四行的 8 个 4 秒窗。
  • ④ 在 ③ 里面，这叫嵌套。同一视频里的回答相互相关；答案模型按相互独立计算。

5停止规则 qmixE1（按预算提前停）

每问完一次，算两个数，判断还要不要接着问。代码在 src/qtl/stop_rules.py（"qmixE1": ("dlsum", "eig")）和 src/qtl/policy.py（calibrate、stop_calls）。阈值原来也记作 c，为了和先验权重区分，本页改记 τ。

后看 dlsum_k = Σ_t | logit p_t(第 k 次回答后) − logit p_t(第 k 次回答前) | 上一个回答让分数变了多少 前看 eig_k = 下一个最佳节点的 EIG 下一个问题还能带来多少信息 r_k = max( dlsum_k 在 validation 全部值中的分位数, eig_k 在 validation 全部值中的分位数 ) r_k ≥ τ 就继续问；第 1 次总是问；每视频最多 8 次
  • τ 怎么定：在 validation 上调 τ，让平均调用次数等于预算 B。只用调用次数，不用标注。B 由使用者按资源设（用户 2026-11-01 裁定）。
  • 第 7 版里：停止规则仍用在 d = 0 的贪心策略上（评审要求），本轮没有改。HateMM 上“贪心 + 停止规则、平均 8 次”比 8 个等长窗低 .017 AP，所以按预算停的曲线和固定 d 的曲线是两条不同的策略，分开报告。

先验 · 第 7 版的来源

网络的位置先验在没见过的视频上只该用十分之一到四分之一

c 中位数 .26 / .09 / .18；去掉 c，AP 降 .025 / .043 / .026

不用任何标签、只看 validation 回答估出来的 c 都远小于 1。视频级 logit 也一样：train 上 AUC .95 / .99 / .93，test 上 .84 / .69 / .69，test 上的校准系数只有 .29 / .26 / .24。网络在训练视频上把回答拟合得太好，到新视频上过度自信。

提问 · 语料决定问法

同一条选择规则，HateMM 选等长窗，HCS 选自适应树

HateMM d = 3 占 82%；HCS d = 0 占 98%

HateMM 上只有两处一起加才涨：只选 d（不加 c）AP .702，只加 c .698–.707，两个都加 .722–.723。先验打折之后，均匀覆盖整段视频才比按先验挑片段好。这和群检验的经典结论方向一致（Ungar 1960，独立同分布条件下：阳性比例超过约 .38 时逐个检验比合并检验好），只作动机，不是本任务的定理。

20261110_prior_weight 第 9、12 节

VLM 回答

VLM 只回答“有没有”，不回答“有多少”

P(Yes) 与仇恨占比的相关 −.06–.16；“全部 vs 部分” AUC .44–.55

含仇恨的节点里，P(Yes) 几乎不随仇恨占比变化。直接问“无 / 部分 / 全部”，在 HateMM、DeHate 上分不清整段仇恨和部分仇恨（HCS .55–.64 弱信号），“有没有”这一维和原来的是 / 否一样。所以节点状态取“含任一仇恨秒”（OR）是对的建模。

E6注意事项与没解决的问题

树的 within 目标只在 HCS 成立。HateMM 上 validation 选出的问法就是单层等长窗；DeHate 上选中深度的 within 比单层低 .010。论文里“树比单层好”只能在 HCS 上主张，HateMM 要写成“按语料选问法”。
trial 用 test 选（规则 7）。validation 选 trial 时第 7 版低不少（HateMM .677 / .868 / .760），论文须同时报。
分数文件取 6 位小数。低于 5e-7 的逐秒概率写成 0，使 HateMM within 偏低：不取整时 .826 → .833（全 trial +.010）；HCS、DeHate 无影响。是否改小数位数待用户裁定。
d 在规则 13 下的读法。8 次时 d = 0 与 d = 3 相当于“EIG 选节点”开或关；评审认为 d 只能作为不主张的超参数。
DeHate seed 3407 的 trial 2、6：CPU 重放与 GPU 搜索的 AP 差 .003–.006，原因未查明；都不是 test 选出的 trial。
