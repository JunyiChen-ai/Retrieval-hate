## W2 — MHC-EN 共识失败归因(不改 src;先跑,产出喂 W3 决策)

对语音承载仇恨无效」分开。

**W2.1 HateMM subclip 抽取 + 三方消融(第二个 EN 数据集做对照)**

  `train_consensus.sbatch` 传 DATASET=HateMM,零代码改动)。
- 判读:若 consensus 在 HateMM(EN)≥ floor → 失败是 MHC-EN 特异(语音承载假设增强);
  若 HateMM 也失败 → "EN/语音承载仇恨上 sub-clip 视觉键失效"为一般现象,W3 的 EN 栈弃用共识。

**W2.2 MHC-EN τ/topk 敏感性(排除"参数点背"解释)**

- 判读:若存在 (topk,τ) 使 EN ≥ floor → 共识可救,进 W3 EN 栈;若全网格皆 < floor →
  E1 结论升级为"EN 共识在该键空间不可救",写死进节点 caveat。

## W4 — 时间演化记忆协议(只新增独立脚本;与 W2/W3 并行,CPU 为主)

**机制(DESIGN_iter3 方法 B):** 在 wave-1 的 temporal split 上形式化 evolving-memory 评测:
头在 temporal-train 上训一次后**冻结**;记忆库分阶段增补,**零重训**。

- **协议:** (a) **static**:memory = temporal-train(过去期),评 temporal-test;
  (b) **+k 增补**:从"新期流"= temporal-val(日期严格介于 train 期与 test 期之间)取 k 个
  带标签样本加进 memory,k ∈ {5,10,20,50},选样策略 random(多 seed 报 mean±std)/
  latest / uncertain(vs static memory 的 kNN vote margin,不用任何 test 信息);
  (c) **reference**:同协议跑随机 split(RAC_video_CLIP 头,--augment False)。
  Leak-safety:temporal-test 永不进 memory;k 不在 test 上调(报全曲线)。
- **指标:** adaptation(+k vs static 的 Δacc/ΔF1 随 k 曲线)、retention(增补不伤已对样本)、
  update cost(应为秒级 faiss add,零重训)。
- **必须声明:** temporal test 正例率 ~24% vs train ~34%(prior shift)+ survivor bias
  (ZH-Hateful 18.8% / EN-Offensive 21.2% 死链)——所有数字对照**同 split 的 static floor**
  与逐 split 重算的多数类基线,不与随机 split 直接对比。
- **实现(脚手架已在,wave-1 已按所有权规则建好,均为独立新文件):**
  `src/train_temporal_head.py`(runtime 注入 temporal loader,run_rac.main 原样复用,
  不改盘上任何现有文件)+ `src/eval_evolving_memory` 职能由 `src/eval_temporal_memory.py`
  承担(READ-ONLY 复用 eval_cross_dataset 的 project_split/knn_vote)。夜间只补跑通 + 补
  sbatch(`scripts/slurm/evolve_memory.sbatch`,新文件),CLIP 特征先行;LoRA 特征版视时间。
- **W4 入库:** 新节点 `experiments/exp-evolving-memory-protocol.md` + ITERATION_LOG 追加。
