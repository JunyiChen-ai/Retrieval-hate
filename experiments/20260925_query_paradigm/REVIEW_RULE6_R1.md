## Checked and found correct (no action)

- **Chain prior, answer factors, label conditioning and g enter the loss as README 7.2.3 states.** `ctree.up` (`ctree.py:89-131`): leaf tables (`:106-116`) put weight 1 on y_t = 0 and exp(s_t) on y_t = 1; `_merge` (`:80-86`) joins adjacent intervals through A(last_L, first_R) and ORs the "any" flags; the answer factor is added on the node's any-flag (`:123`, index 0 → state 1, index 1 → state 2); `logW1` (`:128`) sums the any = 1 root entries under π0 and adds g; `logW0` (`:129-130`) is the all-zero path with the state-0 answer log-likelihoods. `log_evidence` (`:134-141`) returns log P(Y=1 | x), log P(Y=0 | x) (g enters here, s enters for both labels — negatives push s_t down through the partition function), log P(o | Y=1, x) = w1a − w1n (g cancels, as it must) and log P(o | Y=0) = Σ_n A3[n, 0]. `train.py:201-204` selects by label with `torch.where(label > 0.5, ·, ·)`, divides the answer term by the number of answered nodes (`n_obs`, `:195-199`, `clamp(min=1)` for the one train video without queryable nodes) and uses no separate BCE on g in the "tree" objective (BCE only in the "mil" arm, `:205-206`). Chain parameters are in the optimiser (`:162-165`).
- **Batched pass feed.** `Forest([store.T[v] for v in vids], Tm)` with `Tm = f_v.shape[1]` = width of `s` (`train.py:181, 188`); `leaf_row = vid·Tmax + a` with a < T so padded logits are never read (`ctree.py:71, 107`); node ids per video offset by `fo.offs[b]` (`train.py:193`), `A3` written by `index_put` on those global ids (`:198`); `am.loglik` on the concatenated (answers, lengths) in the same order as the ids (`:197`). Float32 throughout training; the −BIG = −1e4 sentinel stays ≥ 9.7e3 below the live entries at every level (per-level normalisation `ctree.py:124-125`), so it never contributes.
- **Final score.** `ctree.marginals` (`ctree.py:144-155`): p_G = σ(logW1 − logW0), E[z_n | Y=1, o] = ∂logW1/∂η_n, per-second score p_G · ∂logW1/∂s_t, float64, matches enumeration. `cpolicy.run_batch` appends `p[b, :T]` (`cpolicy.py:58`) after 0..n answers; `train.at_budget` picks the fixed-8 entry; `evaluate` writes it through `hc.write_scores` → `hc.run_evaluator` → `scripts/reproduction_baselines/eval_baseline_scores.py` (`train.py:271-276`) for every reported test number (fixed budgets, EIG rule, VOI rule); `metrics.json` and `summary["test"]` are the fixed `primary_budget` entry (`train.py:302-303, 313-317`); `search.py:89-97` ranks by it and records the fixed-8 validation numbers for the validation-selected trial.
- **`cpolicy.run_batch`.** Per-video priors from `policy.video_prior` (five-crop mean, no answers) into padded `S`, `G` (`cpolicy.py:37-41`); one `Forest` per chunk, `Asker` tables rebuilt from the current `am` (`:42-44`); node marginal lookup with the video offset `m[off + nodes]` (`:68`); state weights [1−p_G, p_G(1−m), p_G m] (`:69`); EIG argmax or BFS first-remaining (`:70-75`); candidates removed only after being chosen (`:99`); a video whose queryable nodes are exhausted is skipped (`:65-66`) and stops receiving scores/eig entries (`:57`); loop ends at `max_calls` or when no video has a candidate (`:60-61, 77-78`). VOI (`:79-97`) is computed from two batched passes with the chosen node clamped to state 1 and state 2 (`keep` adds −BIG to the other two states, incl. state 0 so p_G → 1 and the pass returns P(y_t = 1 | Y=1, z_n = state, past)) — clamping one node per video in a single batched pass is exact because videos do not interact — and it is computed before the answer is read (`:98-107`). Parse failures count as a call with no factor (`:101-104`), as in revision 0. Flat arm (`:26-28, 58, 105-107`): logit of the zero-answer chain marginal plus the mean state-2/state-0 log-likelihood ratio of asked nodes covering t.
- **Leakage.** `PriorNet.forward(f_a, f_v, mask)` (`model.py:74-85`) is the only network call; it receives no answer tensor (`policy.video_prior`, `train.py:184`). `init_theta`, `loglen` (`train.py:154-159`) use train ids. Chain/answer-model parameters get gradients only from train batches. Checkpoint = validation fixed-8 EIG through the same `Evaluator.run(..., chain=chain)` and `at_budget` (`train.py:235-246`). Thresholds for both adaptive rules are calibrated on validation only (`policy.calibrate([r[rule] for r in val_runs...])`, `train.py:288`) and applied to test. Test labels appear only in the silent-group and pos/neg mean-calls analysis fields (`:296-297, 305-310`). Val/test answers are read only as the simulated oracle.
- **Checkpoint chain.** Best epoch stores `model`, `am`, `chain` state dicts (`train.py:243-246`); all three restored before `evaluate` (`:247-250`) and saved to `model.pth` (`:252-253`); the `Asker` tables are rebuilt from the restored `am` on every `run_batch` call. `DEFAULTS["prior"] = "chain"` (`:66`) so `launch/run_search.sh` → `search.py` → `train.py --config hparams.json` runs the revision-1 method; arms are passed through `--extra-config` with the unknown-key assert (`train.py:333-334`, `search.py:65`).

## Minor (not conclusion-changing, no action required)
