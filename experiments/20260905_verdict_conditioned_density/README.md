# 裁定条件化密度估计（idea discovery 2026-09-05 推荐候选 C7 + C1）——CPU 门（2026-09-05 09:30，本机）

来源：`docs/idea-stage-20260905/refine-logs/FINAL_PROPOSAL.md`。提案第 2 节规定任何 GPU 运行之前先做 CPU 门：只重拟合标注模型（HMM），用统一评测器评"后验单独"的 test 数字，并检验每视频比例估计 q_v = mean_t P(s_t) 是否可用作模块 2 的比例损失目标。

## 模型
`src/verdict_hmm_cond.py::CondEvidenceHMM`：候选 1 的两级 HMM，细裁定发射改为条件发射 P(b30_t = 1 | s_t, c_t) = p[s][c_t]，上下文 c_t = (所在块的粗裁定 b4，前一细裁定 b30_{t−1})。四个臂：`global`（= 候选 1 HMM，1 个上下文）、`b4`、`bprev`、`cond`（4 个上下文）。参数只用 train 视频标签：s=0 侧率由负例计数加正例 s=0 后验质量，s=1 侧率、粗率、A、p0 由正例 EM。第一次运行发现无约束 EM 在 HateClipSeg 的 `cond` 臂标签互换（s=1 的细裁定率低于 s=0），加单调约束 p[1][c] ≥ p[0][c] + .05 后重跑（`gate/<corpus>/`；无约束结果保留在 `gate/<corpus>_unconstrained/`）。

## 门的判据（提案第 2 节，搜索前写定）
1. HateMM 条件后验单独 AP 与 ROC 都高于仅 K4 后验（.591 / .851）至少 .005；HateClipSeg 不低于 .698 / .661。
2. q_v 的 MAE、偏差、与 GT 比例的相关都优于 global 与仅 K4；否则比例损失 thesis 删除。
3. `no_b4`（= bprev 臂）与 `no_bprev`（= b4 臂）隔离增益来源。

## 判定：三条判据都不过，模块 3 候选归档，q_v 比例目标删除
1. 判据 1 不过：HateMM `cond` .510 / .784 低于 global；唯一高于 global 的是 `bprev`（+.043 AP / +.026 ROC），但仍低于仅 K4（.591 / .851）。HateClipSeg 所有条件臂都低于 global（`cond` −.004 / −.008）。
2. 判据 2 不过：所有臂的 q_v 对正例 GT 比例 MAE .34–.51、偏差 −.07 到 −.40（系统性低估）、相关 ≤ .40；q_v 不能作比例损失目标，模块 2 的比例损失 thesis 删除。
3. 判据 3：HateMM 上增益全来自自回归项 b30_{t−1}（细裁定成串），粗裁定条件化反而有害；"粗裁定条件化细裁定可靠性"不成立。

后果：提案第 2 节的模块 3 归档；提案第 3 节的模块 2（scale–rank 分解头）失去比例目标，剩下的 s_v 加性标量按评审自己的算术预期 +.00–.02，落在噪声内，不单独启动。`bprev` 条件化在 HateMM 后验单独 +.043 AP 是一个记录（VLM 细裁定有自相关），但 HateClipSeg 变差，按规则 13 不能作两语料方法；训练后的候选 1（.657）本来就高于任一后验行。
